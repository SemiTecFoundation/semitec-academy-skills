# What to write in each section

| Section | Required | Content | Length |
|---|---|---|---|
| 01 Overview | ✓ | what is built and where it is used; 3–5 checkable objectives (start with a verb) | ½ page |
| 02 Background | ✓ | only the theory needed for this lab; one diagram; point to trainings / books for more | 1–2 pages |
| 03 Preparation | ✓ | tools + versions, board files, downloading the lab files (app → Files), reading/training before, safety | ½ page |
| 04 Procedure | ✓ | `\labstep` per action with a visible result; code via `\srcfile`; `\expected` / `\checkpoint` at key points | 2–4 pages |
| 05 Results | recommended | measurement table; what must be recorded (screenshots, values) | ¼ page |
| 06 Questions | recommended | 3–6 questions on understanding ("why", "what if"), not on memory | ¼ page |
| 07 Report | ✓ | exact list of what is handed in; grading table that sums to 100 % | ¼ page |

Good steps: one action, one visible result, 5–20 minutes each, 4–10 steps per lab.
Checkpoints: where the teacher signs off before the student continues (usually the board demo).
In the app the same steps appear as a checklist with short texts; keep the long explanation in the manual.
